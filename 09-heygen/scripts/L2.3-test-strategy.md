[SCENE 4 — TEACH · Point 1: Layer 1 — Prompt Tests] (0:50–1:55)
SLIDE (max 12 words): Layer 1: Prompt Tests — Fast, Cheap, Many
DIAGRAM DESCRIPTION: Pyramid diagram begins building from the base. Wide bottom layer labeled "Prompt Tests." Callouts: "What you test: System prompt behavior, output format, basic guardrails." "Tools: DeepEval, manual review." "When: Every PR, pre-commit." "Speed: 2–5 seconds each." "Cost: ~$0.01 per test."
SCRIPT:
Layer one — prompt tests. These are the foundation. The widest layer. You run the most of these.

What do you test? Whether the system prompt produces the right tone. Whether the output follows the expected format — JSON, markdown, a specific structure. Whether basic guardrails hold — does the agent refuse to answer off-topic questions?

Each test takes two to five seconds. Costs about a penny in API calls. You can run two hundred of these for two dollars. That's why they sit at the base — fast, cheap, and you want many.

Run them on every pull request. If a developer changes a system prompt, these tests catch regressions before code review even starts. Think of them as the lint checks of AI testing.

[SCENE 5 — TEACH · Point 2: Layer 2 — Component Tests] (1:55–3:05)
SLIDE (max 12 words): Layer 2: Component Tests — Tools, Retrieval, Individual Skills
DIAGRAM DESCRIPTION: Second layer builds on the pyramid. Medium-width layer labeled "Component Tests." Callouts: "What you test: Tool calling accuracy, retrieval quality, single-skill tasks." "Tools: DeepEval, RAGAS, pytest." "When: Every PR, nightly." "Speed: 5–30 seconds each." "Cost: ~$0.05 per test."
SCRIPT:
Layer two — component tests. Here you test individual capabilities in isolation.

Does the agent call the right tool? Give it "Look up order ORD-001." Verify it calls the lookup_order function, not process_refund. Does retrieval work? Ask a question that requires knowledge-base context. Check that the right documents surface and the answer is grounded in them.

You'll use DeepEval for tool-correctness metrics and RAGAS for retrieval-specific evaluations like context precision and recall. Each test runs five to thirty seconds. Costs about a nickel.

Here's the critical insight. Seventy percent of agent bugs live in this layer. The LLM picks the wrong tool. The retrieval pipeline returns irrelevant documents. The agent formats tool arguments incorrectly. If you only write end-to-end tests, you'll know something is broken but not where. Component tests pinpoint the failure.

[SCENE 6 — TEACH · Point 3: Layer 3 — Integration Tests] (3:05–4:10)
SLIDE (max 12 words): Layer 3: Integration Tests — Multi-Step Agent Flows
DIAGRAM DESCRIPTION: Third layer builds. Narrower layer labeled "Integration Tests (Agent Flows)." Callouts: "What you test: Multi-step reasoning, tool chains, conversation flows." "Tools: DeepEval trajectory evals, custom scripts." "When: Nightly, pre-release." "Speed: 30–120 seconds each." "Cost: ~$0.25 per test."
SCRIPT:
Layer three — integration tests. Now you test multi-step flows. The agent receives a complaint, looks up the customer, creates a ticket, and sends a confirmation email. Four steps. Each step depends on the previous one.

This is where goal drift surfaces. The agent starts on track, drifts mid-conversation, and ends up solving a problem the user never had. This is where infinite loops appear — the agent retries a failing tool call twelve times.

You test the full trajectory. Did the agent take reasonable steps? Did it reach the correct outcome? Did it stay within token and time budgets?

These tests run thirty seconds to two minutes each. They cost about twenty-five cents in API calls. You write fewer of them — maybe twenty to fifty for a typical agent. Run them nightly and before every release.

[SCENE 7 — TEACH · Point 4: Layer 4 — System Tests + Security Overlay] (4:10–5:15)
SLIDE (max 12 words): Layer 4: System Tests + Security Scans (Periodic)
DIAGRAM DESCRIPTION: Top of pyramid plus a translucent overlay. Narrow top layer labeled "System Tests (E2E)." Translucent overlay across the full pyramid labeled "Security Scans." Callouts for System Tests: "What you test: Full pipeline — API to response to logging." "When: Pre-release, weekly." "Cost: ~$1–5 per suite." Callouts for Security: "What you test: Prompt injection, PII leakage, jailbreaks." "Tools: promptfoo red-team." "When: Weekly, post-model-update."
SCRIPT:
Layer four — system tests. Full end-to-end. Hit the API, get a response, verify it's correct, check that the trace was logged, confirm the metrics pipeline recorded it. These are slow and expensive. Run them pre-release and weekly. You want ten to twenty of these — covering the critical user journeys.

The security overlay sits across the entire pyramid. It's not a layer — it's a lens. Prompt injection attacks. PII leakage probes. Jailbreak attempts. You run these scans weekly and after every model update. A new model version can change safety behavior without warning. The tool is promptfoo — you'll build a full red-team suite in Module 8.

One stat to remember. Sixty-two percent of LLM security vulnerabilities are introduced by model updates, not code changes. Your CI/CD pipeline catches code bugs. Security scans catch model bugs.
