[SCENE 6 — SHOW / DEMO: Steps 3–5 — Build, Configure, Run] (2:30–4:40)
SCREEN ACTION: VS Code, dark theme. Full evaluation script visible. Walk through each section, highlighting as the voiceover explains. Then switch to terminal and run the evaluation.

```python
# eval_support_agent.py
import json
from deepeval import assert_test
from deepeval.test_case import LLMTestCase
from deepeval.metrics import AnswerRelevancyMetric
from agents.support_agent import run_support_agent

# --- Step 2: Run agent, capture responses ---
with open("datasets/golden_support.json") as f:
    golden_data = json.load(f)

for item in golden_data:
    result = run_support_agent(item["input"])
    item["actual_output"] = result["response"]

# --- Step 3: Create LLMTestCases ---
test_cases = [
    LLMTestCase(
        input=item["input"],
        actual_output=item["actual_output"],
        expected_output=item.get("expected_output", ""),
        context=item.get("context", []),
    )
    for item in golden_data
]

# --- Step 4: Configure metric ---
relevancy = AnswerRelevancyMetric(threshold=0.7, model="gpt-4o-mini")

# --- Step 5: Run with pytest ---
import pytest

@pytest.mark.parametrize("test_case", test_cases, ids=[d["input"][:40] for d in golden_data])
def test_support_agent(test_case):
    assert_test(test_case, [relevancy])
```

Terminal: `deepeval test run eval_support_agent.py`
Show output scrolling — each test case with its score and pass/fail status.
SCRIPT (voice-over):
Here's the full script. Let me walk through it.

Step three — create LLMTestCases from the filled data. A list comprehension turns each dictionary into an LLMTestCase object. Input, actual output, expected output, and context all map to their fields.

Step four — configure the metric. AnswerRelevancyMetric, threshold 0.7, using gpt-4o-mini as the judge. One line.

Step five — the pytest integration. Use `@pytest.mark.parametrize` to create one test per case. The `ids` parameter uses the first forty characters of each input — so the terminal output shows readable test names instead of "test_case_0, test_case_1."

Now run it. `deepeval test run eval_support_agent.py`.

Watch the output. Each test case appears with its name. The metric runs. A score appears. Pass or fail. The whole suite finishes in about thirty seconds for ten test cases. That's roughly three seconds per evaluation — one second for the agent call, two seconds for the LLM judge.

SCRIPT:
Let's read the output. Every test case produces four data points.

The score — a decimal between zero and one. The refund policy test scored 0.92. Strong.

The threshold — your quality bar. Set at 0.7.

The verdict — pass or fail. Score meets or exceeds threshold? Pass. Falls short? Fail.

The reason — this is the diagnostic. Look at the failing test. "The response acknowledges the issue but provides generic troubleshooting instead of creating a support ticket as expected." That tells you exactly what to fix. The agent needs better logic for handling billing complaints — it should create a ticket, not troubleshoot.

Without the reason, you'd see "0.45 — FAILED" and guess. With the reason, you know the fix in under ten seconds. This is the power of LLM-as-judge. The judge doesn't just score — it explains.

One more number. Look at the bottom of the output — the aggregate pass rate. Eight out of ten passed. Eighty percent. Your team can now track this number across releases. If it drops from eighty to sixty-five after a prompt change, you know something broke.
