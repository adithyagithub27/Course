# Atlas — AI Agent Observability & Cost Control (course code)

Student repository for the Udemy course **"AI Agent Observability & Cost Control: LLMOps in Production with OpenTelemetry & Langfuse"**.

**Atlas** is the internal IT/HR helpdesk agent of the fictional *Northwind Logistics* (four department tenants: `ops`, `finance`, `hr`, `eng`). It answers policy questions from a knowledge base, looks up and creates tickets, resets passwords after verification and checks shipments. **The swarm** replays a realistic, deterministic day of traffic with injectable incidents, so you always have telemetry to look at — even with `OFFLINE=1` and no API keys.

> **Version banner (verified 2026-09-28):** Python 3.11+, `langfuse` 4.15 (OpenTelemetry-based SDK), `opentelemetry-sdk` 1.45, `opentelemetry-semantic-conventions` 0.66b0 (GenAI conventions, *incubating: names may change*), `openinference-instrumentation-openai` 0.1.61, `litellm` 1.103, `openai` 2.54, `deepeval` 4.2, `langsmith` 0.14. If your versions differ, see *Troubleshooting*.

## Quick start (10 minutes, no keys needed)

```bash
cd 03-code
make install                 # uv venv + pip install -e ".[dev]"; copies .env.example -> .env
source .venv/bin/activate
make test                    # 401 tests (356 unit, 40 integration, 5 budget gate), all offline, green
make replay                  # OFFLINE=1: a full day (≈10k requests / 4k sessions) into .atlas/spans.sqlite in ~20 s
make console-text            # the Ops Console as text (Streamlit: pip install -e ".[dashboards]" && make console)
make run                     # Atlas on http://localhost:8000 (mock LLM)
curl -s localhost:8000/chat -H 'X-Tenant: eng' -H 'X-User: NW-40213' -H 'content-type: application/json' \
     -d '{"message":"How do I connect to the VPN from home?"}' | jq
```

With real keys: set `OFFLINE=0`, `OPENAI_API_KEY`, and the `LANGFUSE_*` keys in `.env`; every span then also lands in Langfuse (`OTEL_EXPORTER=langfuse` or any exporter — Langfuse attaches to the same TracerProvider).

## Offline mode

Datasets for the incident labs live in `incidents/incident-0*/` (`spans.jsonl` + `scores.jsonl`, ~5 MB each, regenerated byte-identically by `make incidents`).

`OFFLINE=1` swaps the OpenAI client for `app/mock_llm.py`: a deterministic mock that returns real `openai` response objects with realistic token usage (including prompt-cache hits and reasoning tokens), simulated TTFT/latency per model, and scenario hooks. Spans go to the in-process TracerProvider **and** a local SQLite store (`ATLAS_LOCAL_STORE`), which the Ops Console, the evals and the CI budget gate read. Nothing in `make test` touches the network.

Scenario names (`ATLAS_SCENARIO`, `make ... SCENARIO=`, `/chat {"scenario": ...}`): `loop`, `ticket_flaky`, `context_bloat`, `retry_storm`, `slow_provider`, `prompt_regression`. Incident presets for `make replay SCENARIO=...`: the six scenario names plus `cost_spike`, `latency_regression`, `quality_drift`, `mixed`.

## The cost story (Section 6)

The default replay day is 4,000 sessions ≈ 10,100 requests. `make replay` starts from the **baseline** (the Makefile passes `ATLAS_PROMPT_CACHE=$(CACHE) ATLAS_CONTEXT_DIET=$(DIET) ATLAS_ROUTER_MODE=$(ROUTER)`, all `0` unless you set them), so each lever is a flag you switch on. Running `python simulator/replay.py` directly uses your `.env` defaults (cache and diet on). Measured with seed 7:

| Configuration | Flags | Daily cost | Δ |
|---|---|---:|---:|
| Baseline (no cache, no diet, no routing) | `make replay` | $56.28 | — |
| Prompt caching | `CACHE=1` | $37.00 | −34.3 % |
| Context diet | `DIET=1` | $41.99 | −25.4 % |
| Small-model-first routing | `ROUTER=1` | $47.07 | −16.4 % |
| Caching + diet | `CACHE=1 DIET=1` | $22.71 | −59.6 % |
| All three | `CACHE=1 DIET=1 ROUTER=1` | $19.07 | −66.1 % |

Every figure the scripts quote comes from `01-curriculum/numbers-card.md` (regenerated from real runs).

Prices come from `litellm.model_cost` when available, else the pinned table in `src/northwind/pricing.py`.

## Troubleshooting

- **`update_current_trace` does not exist.** Langfuse 4.x sets trace-level `session_id`/`user_id`/`tags`/`metadata` with the `propagate_attributes(...)` context manager (`telemetry/langfuse_setup.py::trace_attributes`). The raw span attributes are `session.id`, `user.id`, `langfuse.trace.tags`.
- **My plain OTel spans don't show in Langfuse.** By default Langfuse exports only spans with `gen_ai.*` attributes or its own; we pass `should_export_span` so every `atlas` span is exported.
- **`opentelemetry-instrumentation-openai-v2` import error.** Known broken at verification time; use OpenInference (`telemetry/openinference_setup.py`).
- **tiktoken wants to download an encoding.** `tokens.py` never needs it; set `ATLAS_USE_TIKTOKEN=1` only if the encoding is already cached.
- **`make replay` is slow.** The default day is 4,000 sessions (~20 s). Use `SESSIONS=400` for quick iterations.
- **Streamlit not installed.** `pip install -e ".[dashboards]"` or use `make console-text`.
- **LiteLLM import takes seconds.** It is imported lazily and only in router mode with `OFFLINE=0`; `pricing.py` uses the pinned table unless `use_litellm=True`.
- **Budget gate fails.** Print the numbers with `pytest tests/budget -ra -s`; loosen with `BUDGET_P95_LATENCY_MS` / `BUDGET_COST_PER_SESSION_USD` or fix the regression. To make it fail on purpose: `BUDGET_GATE_INCIDENTS=latency_regression make budget-check`.
- **Prometheus label explosion.** Labels are limited to `telemetry.metrics.ALLOWED_LABELS` and checked by a unit test; unknown `X-Tenant` values collapse to `other`.
